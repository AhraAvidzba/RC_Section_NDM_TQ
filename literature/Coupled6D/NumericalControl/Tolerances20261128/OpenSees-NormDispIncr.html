3.2.4.2. NormDispIncr Test

test NormDispIncr $tol $iter <$pFlag> <$nType> <$maxTol>
ops.test('NormDispIncr', tol, iter, pFlag, nType, maxTol)

Argument

Type

Description

$tol

float

tolerance used to check for convergence

$iter

integer

maximum number of iterations before the step fails

$pFlag

integer
print flag (optional: default = 0):
0 print nothing
1 print the norms at each iteration
2 print the norms and number of iterations at the end of a successful step
4 print the norms, and the \(\Delta \mathbf{U}\) and \(\mathbf{R}(\mathbf{U})\) vectors, at each iteration
5 if the step fails to converge in $iter iterations, print a warning BUT RETURN SUCCESS
6 as 2 and 5 together

$nType

integer

type of norm: 0 max-norm, 1 1-norm, 2 2-norm, … (optional: default = 2)

$maxTol

float

the test fails at once if the norm exceeds this value, e.g. because the solution is diverging (optional: default = 1.7e307, i.e. no limit)

Discussion

This command is used to construct a convergence test that uses the norm of the solution of the matrix equation, i.e. the \(\mathbf{x}\) vector in \(\mathbf{A} \mathbf{x} = \mathbf{b}\), to decide whether convergence has been reached: the step has converged when \(\left\| \mathbf{x} \right\| \le tol\). What the right-hand side \(\mathbf{b}\) and the solution \(\mathbf{x}\) are depends on the integrator and constraint handler. Usually, though not always, \(\mathbf{b}\) is the unbalanced force and \(\mathbf{x}\) the displacement increment.

Note

  1. When using the Penalty Constraint Handler constraint handler, the large forces needed to enforce the constraints are included in the \(\mathbf{x}\) vector. If the penalty factors are very large, these can be large even for very small changes in displacement.

Example:

The following example creates a NormDispIncr test with a tolerance of 1.0e-8 on the 2-norm of the displacement increment, and a maximum of 10 iterations.

test NormDispIncr 1.0e-8 10

ops.test('NormDispIncr', 1.0e-8, 10)
