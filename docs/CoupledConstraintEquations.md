# Материальная координата в связанном равновесии

`ICoupledScalarConstraint` задаёт читающую скалярную функцию в тех же
нормированных координатах, что `ICoupledEquationSystem`. Нулевое значение
функции соответствует заданному уровню материальной координаты.
`CCoupledConstraintEquations` удерживает этот уровень при каждом чтении
полной невязки, включая пробы численной производной и пробные шаги.

Вектор ξ содержит n нормированных координат. Первые n−1 координат
описывают поле и условия его однозначности, последняя — приращение
множителя нагрузки λ в принятом численном масштабе. Исходная система
возвращает n невязок; её первые n−1 строк сохраняются адаптером.

Для исключения выбирается индекс p < n с наибольшим ненулевым модулем
производной скалярной функции g по ξ. Отображение π сохраняет остальные
координаты и находит πₚ из условия g(π) = 0. Значение g включает вычитание
заданного уровня; точность отображения имеет те же единицы, что g.
Для материального отклика сечения это МПа.

Преобразованная система имеет вид:

\[
H_i(\xi)=F_i(\pi(\xi)),\quad i<n;
\qquad H_n(\xi)=\xi_p-\xi_{p,0}.
\]

Здесь Fᵢ — исходная невязка, Hᵢ — невязка адаптера, ξₚ,₀ — исходное
значение исключённой численной координаты. Последняя строка задаёт
численную однозначность. Действительное физическое поле получается
из π(ξ), поэтому после решения обязательно вызывается `TryMap`.

При gₚ ≠ 0 производная исходных силовых строк вычисляется по правилу цепочки:

\[
\frac{\partial H_i}{\partial\xi_j}
=J_{ji}-J_{pi}\frac{g_j}{g_p}\quad(j\ne p,\ i<n),
\qquad
\frac{\partial H_i}{\partial\xi_p}=0.
\]

Здесь Jⱼᵢ = ∂Fᵢ/∂ξⱼ, gⱼ = ∂g/∂ξⱼ; первый индекс матрицы VBA является
столбцом. Производная последней строки равна единице в столбце p
и нулю в остальных столбцах. Координата нагрузки остаётся в системе.

`CCoupledMaterialConstraint` читает пробную поверхность CDP либо
выбранное главное напряжение ASD через `CCoupledReinforcedResponse`.
Точка, продольная станция, индекс границы и заданный уровень передаются
явно. Координата станции использует тот же `SPATIAL_HALF_STEP`, что
исходная сборка. Полевой вектор восстанавливается через сохранённые
точные копии seed и scales. Геометрические производные готовятся один
раз; материальный градиент читается для текущей пробы.

`CCoupledNewtonSolver.CreateMaterialConstraint` работает внутри открытого
контекста нормированных уравнений. `EquationContext` различает повторные
открытия уравнений даже при одинаковой принятой истории. Материальная
координата проверяет одновременно эту личность и `AcceptedRevision`.
Историей управляет владелец; прямое изменение материальных буферов
в обход владельца во время действия контекста недопустимо.

При отсутствии скалярного корня, нулевой производной выбранной координаты
или исчерпании бюджета `TryMap` возвращает False. Это численный отказ.
Неподготовленные размеры и устаревший контекст дают понятную ошибку
подготовки. Ни один из этих исходов сам по себе не определяет разрушение.
`ProjectionCalls` учитывает скалярные чтения отдельно от запросов полной
невязки численного решателя; число скалярных поправок ограничено.

Для подключения к продолжению вызывающая сторона выбирает событие по
подготовленной модели, создаёт координату и адаптер, затем передаёт
адаптер существующему решателю `ICoupledEquationSystem`. Перед принятием
требуются `TryMap`, повторная полная силовая проверка в восстановленном
поле и действующие проверки направления, неопределённости λ и предельных
состояний. Выбор уровня материальной координаты относится к управлению
численным шагом; он не заменяет выбранный пользователем LoadPath
и критерии несущей способности.

Исследовательский `CCoupledControlConditionTest` сравнивает градиенты возможных управляющих
координат при неизменных первых n−1 строках исходной матрицы. На вход
`TryInitializeTest` поступает полная квадратная матрица в тех же нормированных
координатах ξ. Каждая строка делится на её евклидову норму. Полученная
матрица B факторизуется существующим `CCoupledLinearSystem`; n обратных
подстановок дают L₀ = B⁻¹. Нулевая строка или отказ LU делают такую
линейную опору непригодной для сравнения.

Для кандидата `TryRankTest` нормирует его градиент c до единичной длины
и заменяет последнюю строку B на cᵀ. Обратная матрица получается без
новой факторизации:

\[
v=L_0e_n,\qquad t^{\mathsf T}=c^{\mathsf T}L_0,\qquad
d=t_n,\qquad
L=L_0+\frac{v(e_n^{\mathsf T}-t^{\mathsf T})}{d}.
\]

Здесь L₀ — обратная исходная матрица, eₙ — последний единичный столбец,
v — направление, сохраняющее первые n−1 однородных уравнений,
c — нормированный градиент кандидата, tᵀ — преобразованная строка,
d — её последняя компонента, L — обратная матрица с новой управляющей
строкой. При d = 0 кандидат не устраняет вырождение и отклоняется.
Нулевой градиент также непригоден для управления.

Возвращаемая оценка — норма Фробениуса ‖L‖F. Она сравнима для всех
кандидатов одной подготовленной опоры: все строки прямой матрицы имеют
единичную длину, поэтому её норма Фробениуса равна √n и оценка числа
обусловленности равна √n·‖L‖F. Меньшая оценка предпочтительна только
по линейной обусловленности. Дополнительно возвращается
|cᵀv|/‖v‖₂ — модуль косинуса управляющей строки с направлением
равновесия. Эти величины не подтверждают существование нелинейного
решения, достаточный прирост λ или физическую несущую способность.

Внутренний вызов `CCoupledNewtonSolver.TryDeformationStep` допускает явный
`referenceLambda` — множитель последнего принятого состояния для направленного
восстановления CDP-перехода. Значение по умолчанию равно нулю; штатный
`CCoupledDeformationContinuation` использует именно его. При нуле применяется
обычный гибридный резерв, без наблюдателя материальных пересечений.
Пользовательского параметра для выбора точки материала нет.

При положительном `referenceLambda`, трёх подготовленных железобетонных
откликах и остатке не менее четырёх поправок резервируется до четырёх
поправок, но не более половины остатка. Полный разностный Newton использует
тот же `ICoupledEquationSystem`, центральный шаг 10⁻⁶·(1+|ξⱼ|) и до 21
проверенной доли поправки с уменьшением вдвое. Приёмка доли требует
‖F(ξ+αd)‖₂ ≤ (1−10⁻⁴α)·‖F(ξ)‖₂; здесь ξ — нормированные координаты,
d — решение полной линеаризованной системы, α — доля поправки, F — исходная
невязка. Все пробы входят в общий бюджет вызовов и поправок одного шага.

Читающий `ICoupledDifferenceObserver` разрешает сохранять лишь фактически
вычисленные пары, для которых материал подтверждает пересечение CDP.
Из подходящих столбцов полной матрицы выбирается наибольшая норма
разностной асимметрии после нормирования строк евклидовыми нормами
касательной. Последняя подходящая полная матрица заменяет наблюдение;
частичная матрица его не публикует. Данные очищаются при каждом новом
`TrySolve`, а наружу возвращаются независимые копии.

Для выбранной станции уровень скалярного управления берётся из исходного
прогноза того же шага. Знак соответствует изменению её CDP-координаты;
модуль шага равен максимальному изменению CDP-координаты бетонных точек
в этом направлении по всем трём продольным станциям. Это численная мера
шага. Диаграммы, физические предельные деформации и силовой LoadPath
ею не меняются. Приёмка восстановленного поля требует полной исходной
силовой проверки и λ > referenceLambda + 8·RelTolerance·(1+|referenceLambda|)
+ uncertainty. Здесь uncertainty — фактическая оценка погрешности λ по
сопряжённой системе в найденном поле; она возвращается вместе с новым
управляющим вектором через `CopyRecoveredControl`.

Явный направленный вызов не принимает историю автоматически и не
определяет несущую способность. Вызывающая сторона отдельно проверяет
ориентацию поля, предельные состояния, пригодность приращения λ и только
затем принимает состояние. Результат отдельного перехода не заменяет
проверку полного поиска и сохранённой книги.
