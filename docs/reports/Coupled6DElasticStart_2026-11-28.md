# Автоматический упругий старт ASD, 28.11.2026

В частной книге реализован автоматический выбор стартового масштаба по упругому отклику самого сечения. Независимо подтверждены его расчёт и одинаковый физический размер для восьми номиналов Mx обоих знаков. **Устойчивость и ускорение поиска предела этот вариант не обеспечил:** исправленные холодные Mx± завершились NumFail без предельной точки. Кандидаты1203/1204 в рабочую выдачу не приняты. Публичные исходники, книга и полный дамп не изменялись; принятая частная база1186 сохраняется.

## Автоматическое правило

Подготовленная упругая факторизация решает единичное направление выбранного LoadPath. Общий оператор восстанавливает компоненты деформации во всех материальных точках на трёх осевых станциях. Максимальная абсолютная инженерная компонента ограничивается численным масштабом10⁻⁵; начальный λ пользователя остаётся верхней границей. Поиск λ уточняется тем же коэффициентом, без ослабления заданной точности. Материалы, критерии равновесия, путь, постоянные компоненты, maximumLambda и локальный лимит30 не меняются. Это численное правило старта, а не новый предел материала и не доказанный оптимум.

Для контрольного300×500 мм с четырьмя угловыми φ20 A400 и замкнутым φ8 A240/150 получено ограничение начального физического момента **4,558183772 кН·м**. Первый фактически принятый подшаг обоих знаков равен1,139545943 кН·м. Независимая полная упругая матрица, собранная из геометрических операторов, воспроизвела эти величины. При номиналах Mx=±10,±50,±100,±1000 кН·м физическое ограничение одинаково с относительной точностью10⁻¹². Эта проверка не доказывает одинаковые полные нелинейные истории или пределы при разных номиналах.

Геометрия, ASD и сталь полностью совпадают с [исходным исследованием](Coupled6DMxScale_2026-11-27.md). Hpost=1500 МПа сохраняется только в наследованном контрольном примере для причинного сравнения; он не становится рабочим наклоном. Пользовательский контракт фактических диаграмм/вспомогательной прибавки не более1% остаётся обязательным.

## Обнаруженная и исправленная ошибка тестового варианта

1203 использовал публичный CCoupledElasticState.Solve для численной оценки. Этот метод закономерно записывает ResultMeta завершённого упругого расчёта. Затем второй ASD-повтор читал этот статус как результат подготовки операторов и выходил до поиска. Возвращался пустой результат с OK без какой-либо предельной точки. Это ошибка1203, а не физический успех и не изменение ранее подтверждённого109,8 кН·м.

1204 добавляет CopyVerifiedElasticLoadField в CCoupledElasticState. Метод переиспользует готовую факторизацию, общие проверки исходного равновесия и интегралов шести усилий; копирует поле без записи ResultMeta и без материального коммита. CCoupledNewtonSolver использует этот читающий метод. Фактическая сохранённая269-компонентная книга сверена с исходниками: относительно1203 изменены только эти два класса,267 остальных компонентов неизменны. Само автоматическое правило и все физические критерии сохранены.

Отдельная проверка контракта отклоняет OK/FAIL поиска предела без реальной предельной точки. Оба1203 записаны как воспроизводимые отрицательные контроли с contract_passed=false. Оба1204 имеют корректный NumFail с подтверждённой нижней оценкой. Проверка полей OpenSees сама по себе не выдаёт алгоритму успешный итог поиска.

Следующий приоритет — зависимость управления и численного разрешения λ от масштаба направления нагрузки: в частности, существующее LoadResolution=8·relTol·(1+|λ|) не является физически инвариантным к перенормировке номинала. Требуется согласовать его с фактической неопределённостью усилий и проверить применение коэффициента стартового шага во втором повторе: ограничение min(initialLambda,elasticScale) может дать одинаковый физический старт обеим попыткам. Это проверяемые гипотезы, а не уже внесённые исправления. Не увеличивать бюджеты и не объявлять фиксированную пару параметров универсальным оптимумом. Предусмотреть автоматическую адаптацию без ручного изменения момента пользователем.

Рабочая интеграция частных численных исправлений, универсальная поперечная арматура, все LoadPath, Q/NMTQ, CDP, дальнейшая независимая/экспериментальная/сеточная и нормативная проверка остаются в исходном объёме ТЗ. Полный ON/OFF/UI/часовой набор не запускался. Основная цель активна.
