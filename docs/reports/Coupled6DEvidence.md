# Воспроизведение доказательств связанного расчёта

Из корня проекта запустите сценарий с путём к новому файлу отчёта.

```powershell
python -B -X utf8 tools/verify_coupled_6d_evidence.py --output Coupled6DReplay.json
```

Проверено с Python 3.12.10, NumPy 2.3.5, SciPy 1.18.1 и PyMuPDF 1.28.0.
Пакеты нужны проверяющим сценариям, а книга Excel использует VBA.
Для физических проверок §331–332 нужны локальные первичные PDF.
В свежей копии проекта их восстанавливают по [реестру литературы](../../literature/Coupled6D/README.md).
Для версии репозитория в другой папке укажите `--repo`.

[Манифест](Coupled6DEvidence.json) фиксирует SHA-256 установленной пары
XLSM и выгрузки VBA, 102 архива и команды 108 проверок с указанием разделов
[журнала](Coupled6DProgress.md). Архивы проверяются до распаковки. Для двух нативных
проверок Kani нужный исторический XLSM и два зависимых архива
извлекаются из указанной ревизии Git. Текущая рабочая книга
проверяется отдельно по собственному хешу.
Каждый распаковывается в отдельную временную папку. Для проверок с явным
файлом результата сценарий требует заново создать файл и получить
ожидаемый SHA-256. Остальные архивные сценарии самостоятельно сверяют
численные данные и возвращают подтверждающую строку. При любом сбое
сценарий завершается с ненулевым кодом.

Комплект охватывает повтор материальных траекторий, независимую сборку
равновесия и истории Kani, MVT2 и HardShear, а также диагностику
касательных, допуска равновесия, продвижения по фактической деформации, последовательных поправок и физических контрольных расчётов по §417 включительно.
Источник каждой нативной записи
установлен по квитанциям в её архиве. Некоторые записи относятся
к более ранним сборкам. Их исходные ревизии указаны в README архивов.
Офлайн-повтор не открывает книгу и не создаёт новых результатов НДС.
Последний повтор прошёл все 108 проверок. Результат сохранён в
[протоколе](Coupled6DEvidenceReplay.json).

Полный нативный запуск выполняется по [плану приёмки](../ValidationPlan.md)
и [часовому плану](../FocusedValidationPlan.md). Открытые физические
и нативные проверки перечислены в [матрице требований](Coupled6DAcceptance.md).
