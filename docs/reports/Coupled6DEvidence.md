# Воспроизведение доказательств связанного расчёта

Из корня проекта запустите сценарий с путём к новому файлу отчёта.

```powershell
python -B -X utf8 tools/verify_coupled_6d_evidence.py --output Coupled6DReplay.json
```

Проверено с Python 3.12.10, NumPy 2.3.5, SciPy 1.18.1 и PyMuPDF 1.28.0.
Пакеты нужны проверяющим сценариям, а книга Excel использует VBA.
Для физических проверок §331–332 нужны локальные первичные PDF.
В свежей копии проекта их восстанавливают по [реестру литературы](../../literature/Coupled6D/README.md).
Для версии репозитория в другой папке укажите `--repo`.

[Манифест](Coupled6DEvidence.json) фиксирует SHA-256 установленной пары
XLSM и выгрузки VBA, 292 архива и команды 311 проверок с указанием разделов
[журнала](Coupled6DProgress.md). Архивы проверяются до распаковки. Исторические входы
для нативных проверок Kani и проверки установки по §420 извлекаются из
указанных ревизий Git. Для пяти исходников §420 закреплены хеши до и после
восстановления окончаний строк CRLF. Текущая рабочая книга сверяется
по собственному хешу.
Каждый распаковывается в отдельную временную папку. Для проверок с явным
файлом результата сценарий требует заново создать файл и получить
ожидаемый SHA-256. Остальные архивные сценарии самостоятельно сверяют
численные данные и возвращают подтверждающую строку. При любом сбое
сценарий завершается с ненулевым кодом.

Офлайн-случай по умолчанию ограничен 90 с. Для трёх новых механических
проверок §604 с несколькими полными историями в манифесте явно задано
`timeout_seconds = 300`. Это время проверяющего сценария, оно не меняет
допуски равновесия, физические критерии или ожидаемые результаты.

Комплект охватывает повтор материальных траекторий, независимую сборку
равновесия и истории Kani, MVT2 и HardShear, а также диагностику
касательных, допуска равновесия, продвижения по фактической деформации,
последовательных поправок и физических контрольных расчётов по §604 включительно.
В §592 исправлено сравнение смешения повреждений ASDConcrete3D с учётом
R(cdf), повторены 96 нативных обновлений и ограниченная спектральная диагностика.
В §593 проверены дискретизации, собственный перенос начального поля и
30 нативных управляемых шагов уточнённой модели. Из общего принятого
префикса независимо решены те же 30 контрольных целей; OpenSees повторил
484 380 материальных обновлений. Вспомогательные архивы содержат точные
исходные книги и CFB-контейнеры; они восстанавливаются по закреплённым хешам.
Источник каждой нативной записи
установлен по квитанциям в её архиве. Некоторые записи относятся
к более ранним сборкам. Их исходные ревизии указаны в README архивов.
Офлайн-повтор не открывает книгу и не создаёт новых результатов НДС.
В §600 проверены общий поиск по среднему сдвигу, изолированный наблюдатель,
точный VBA четырёх книг и независимые уравнения отдельных принятых историй.
Тайм-ауты сохранены как незавершённые области. Максимум 81,199797 кН
не объявляется подтверждённой несущей способностью.
В §601 проверены пространственная мера по отвергнутой поправке,
автоматическое продолжение до 85 полей, другая история из 108 полей,
точный VBA пяти книг и независимые остатки исследовательских проб.
Физический предел не подтверждён; отрицательные результаты сохранены.
В §602 проверены ревизии принятой истории, полная заблокированная
поправка, точный VBA трёх вариантов и собственные пути 87/90/98/108 полей.
Диагностика 15 состояний точки №63 уточнила причину конечного расхождения.
Расширение малой поправки отвергнуто; физический предел остаётся открытым.
В §603 проверены алгоритмическая касательная замкнутого ASD, точный
VBA и независимые уравнения двух фактических историй. В §604 проверены
знаковая граница, семь нативных вариантов, отрицательные контроллеры,
149 равновесий общего продолжения и отдельная точная цель λ=1.
Диаграммы и допуски сохранены; физический предел остаётся открытым.
В [протоколе](Coupled6DEvidenceReplay.json) сохранены 305 предыдущих
результатов и шесть заново выполненных случаев §604, всего 311.
На этой контрольной точке повторялись только новые случаи из отдельно
распакованного архива. Полный повтор всех архивов заново не запускался.

Полный нативный запуск выполняется по [плану приёмки](../ValidationPlan.md)
и [часовому плану](../FocusedValidationPlan.md). Открытые физические
и нативные проверки перечислены в [матрице требований](Coupled6DAcceptance.md).
